# 反洗钱尽调业务优化详细计划书 v3

编制日期：2026-09-05。  
项目：`D:\JCode`，AML 智能反洗钱尽调 Agent 平台。  
依据：[本轮修改验收](../reviews/remediation-acceptance-v3-2026-09-05.md)、[业务前沿调研与差距分析](../research/aml-business-frontier-2026-09-05.md)。  
状态：**可供实施的业务优化方案；本文件中的新增业务功能、迁移和指标目标尚未交付或达成。**

## 1. 总体建议

以“分析员能解释异常、复核员能复现判断、客户能得到与风险相称的处理”为业务目标，建设具有持续客户尽调、可核验证据、受益所有人核验、资金关系辅助调查和报告质检能力的系统。

先修复剩余验收缺陷并建立真实流程测试基线，再做业务优化。近期最值得交付的是“客户背景 → 异常解释 → 证据核验 → 人工决定 → 可复现的报告”，而不是直接增加模型数量或自动决策权限。

### 1.1 范围假设

- 保持 `PRODUCT.md` 中的中国商业银行本地演示/面试展示定位，使用合成或脱敏数据；真实机构接入另设项目。
- 复用 Vue/Spring Boot/MySQL/Redis/pgvector、冻结快照、Outbox、角色和现有调查契约。
- 国际标准与研究用于产品设计；国内现行要求、机构内部政策、前沿实验分别标记，不混为一套自动执行规则。
- v1 案件仍由人工形成最终决定。AI 可以整理材料、解释线索和建议下一步，不能直接对外报送、限制账户或代替人作最终结论。

## 4. B1：从材料引用升级为可核验证据

### 4.1 业务问题与用户故事

目前 `InvestigationEvidenceLink` 证明有人录入了某类引用和分析，不能自动证明该材料存在、仍有效或足以支持本次判断。EDD 已有来源系统、引用和哈希，应复用这些能力。

分析员应能打开一条判断，看到其对应原始材料、相关页/字段/交易、获取和核验时点、支持方向及局限；复核员应能独立判断证据是否足够。

### 4.2 对象和业务规则

- 新增统一证据目录 `EvidenceArtifact`：来源系统/原始引用、内容哈希、文件或记录类型、获取时点、适用时间、授权范围、核验状态、核验人和版本。
- `EvidenceLink` 只负责证据与案件/假设的关联：证据版本、页码/字段/交易 ID 定位、支持或反证、相关性说明。相同材料可复用引用，不能把另一案件的结论一起继承。
- 核验状态区分未核验、已核验、存在争议、已撤销；材料时效由业务规则判断。缺资料不是“已排除风险”；材料哈希只能证明内容一致，不能证明真实。
- 为每个剧本定义必答问题、证据适用条件和未解决项；只具备证据类型不得直接等于问题已解决。
- 决策记录保存事实、推断、未知、反向解释四类内容。对关键反证给出处理理由，不能静默忽略。

### 4.3 法规依据与保存政策

1. 保留当前 manifest 的来源、有效期和摘要类型；新增正式原文的条款定位与内容校验。摘要标题不得伪装成原法条编号。
2. 将官方原文、人工摘要和机构政策分层，返回引用时显示类型、文号、版本和适用日期；尚待领域审核的条款不能因一个 APPROVED 字段自动获得真实专家背书。
3. 记录业务事实发生时点和当前决策时点，按具体适用规则选择版本。历史报告继续引用原已冻结版本，新决定绑定本次政策版本。
4. 客户身份记录和交易记录设置独立保存起算事件；法律最低期限来自现行规则，不与助手聊天的短期留存混用。支持调查保留标记、受控导出和到期审查；本期不自动删除历史业务数据。[《反洗钱法》第三十四条](https://www.npc.gov.cn/npc/c2/c30834/202411/t20241108_440887.html)

### 4.4 落地范围

扩展 `investigation`、`review/EnhancedDueDiligenceEvidence` 和 `dossier`；为现有 EDD 材料建立适配引用。新增证据查询/核验接口及详情页证据卡；由后端校验访问范围和核验权限。新增迁移使用实施时下一个未占用版本，不修改已发布 V25/V26。

**验收：** 伪造/不存在的引用不能变为已核验事实；源材料撤销后新决定被阻断或要求明确处理；历史快照仍可回放；旧 EDD 材料可查；无权限不能读取原文；同一材料的各处引用保持可追溯。

## 5. B2：建立客户风险档案和持续尽调

### 5.1 目标流程

```mermaid
flowchart LR
    A[客户资料或交易出现变化] --> B[记录变化事实与来源]
    B --> C[确定需复核的风险因素]
    C --> D[生成有责任人和期限的尽调任务]
    D --> E[分析员核验并说明判断]
    E --> F[复核客户风险与后续措施]
    F --> G[保存新版本及下一次复核安排]
    G --> A
```

案件的 DONE 结束一次调查；客户风险档案继续存在。新事件生成新任务或新关联案件，不能改写旧案的冻结事实。

### 5.2 对象与字段

| 对象 | 建议内容 | 与现有模型关系 |
|---|---|---|
| 客户尽调档案 | 客户类型、业务目的、经营/职业信息、预期交易范围/渠道/地区/对手、资金来源与用途、资料来源及缺口 | 扩展 `CustomerProfile` 的业务含义，通过版本化 DTO 渐进接入 |
| 客户风险评估 | 固有风险因素、已采取措施、剩余风险、评估理由、证据和政策版本、人工审核 | 独立于 `CaseEntity.riskLevel`，不拿单案模型评级替代 |
| 尽调策略 | 简化/标准/强化、适用条件、必答问题、禁止简化条件、复核频次策略 | 与调查剧本协同；政策可版本化，但规则变更需测试和审核 |
| 变化事件 | 变更前后事实、来源、发生/发现时间、客户 ID、幂等事件键 | 使用 Outbox 派生任务，防止重复资料更新重复建案 |
| 持续尽调任务 | 触发原因、责任人、截止时间、缺失材料、状态、结果 | 可复用 EDD 工作项模式，避免另造通用流程引擎 |

### 5.3 风险和工作量分开处理

1. 在页面同时显示客户风险、此次案件疑点、证据完整度和操作优先级，解释各自含义。
2. 简化尽调是减少重复/不必要的材料要求，不是自动排除已有可疑线索；有不能合理解释的异常或资料问题时升级工作深度。
3. 同行业或同地区不是自动定性依据；优先比较客户自己已核验的预期行为和实际变化。
4. 资料缺失单独显示，不用一律调低风险或一律判高来掩盖未知。
5. 新交易、新名单版本、重要经营变化、权益/控制关系变化、资料到期可触发复核。具体频次与触发阈值来自适用规则及机构政策，不由 LLM 随意生成。

### 5.4 首批范围与验收

首批选择个人客户和普通境内企业两类，不一次覆盖所有组织形式。新增客户详情中的“当前画像/变化/待复核任务”三块，复用 `CustomerDataPort`、客户页和运营队列。

验收案例：合法季节性经营增长有明确凭证时可形成合理解释；同样表面异常但缺乏业务背景的案件继续调查；同一事件重复投递只产生一个任务；新风险版本不改变旧案快照；单案排除后新变化仍能触发复核。

## 6. B3：受益所有人识别核验与差异处理

### 6.1 业务闭环

客户申报与可靠来源 → 关系和候选识别 → 多来源核对 → 差异分类/补证 → 人工核实 → 保存结果并建立变化复核。

当前 `ShareholdingRecord(holder, holderType, ratio, level)` 缺少关系两端和核验过程。先补数据语义，再提升自动推理。

### 6.2 设计与实施

1. 新增主体及权益/控制关系对象：两端主体 ID、主体类型、关系类型、比例、有效期间、原始来源、核验状态。权益比例与协议/实际控制分别表达。
2. 由确定性计算产生权益路径候选，保留计算过程；未知持股、循环关系、资料矛盾要显式展示，不能用“未算到”表示不存在。
3. 识别策略覆盖权益和实际控制维度，并对不同组织形式配置适用规则。候选不是最终已核验人；首批仅支持普通公司，信托等形式显示需专门流程。
4. 区分客户申报、可靠独立材料、备案查询结果和分析员核验记录；来源不一致时进入差异任务，禁止自动覆盖为某一来源。
5. 差异记录保存发现日期、内容、重大性判断、理由、证据、处理人和结果；配置适用的时限/工作日日历及升级提醒。外部差异报告在演示中只生成待处理任务，不假称已连接监管系统。
6. 明确简化/豁免前提及其证据，不以“股权简单”代替适用条件判断；信息变更产生新版本，保留旧核验结果。

### 6.3 页面、接口和验收

在复杂股权假设下增加“关系表/候选/来源差异/核验结果”；图形仅辅助展示，全部关键信息可在表格读取。API 按案件和主体限定范围，核验提交携带预期版本并写审计。

验收涵盖直接/间接权益、实际控制但低持股、同名不同主体、未知层级、来源差异和后续控制关系变更。按现行办法核对边界及组织形式，不把所有关系压成一个百分比。B3 规则由领域审核后冻结测试样例。

## 7. B4：资金关系与网络诈骗场景辅助调查

### 7.1 先补数据契约

为交易增加稳定 ID、账户 ID、对手主体 ID、来源系统、交易/入账时间、方向、币种和源记录版本；未知对手使用独立的未知标识，不能把所有空值并成同一人。保留原币种，换算分析需有汇率日期和来源。

当前 30/90/180 天窗口可保留为统计入口；案件研判中的路径必须引用案件冻结的交易集合，实时客户视图要标明其不同截止时点。

### 7.2 分两步实现

1. **可解释关系规则。** 用关系表及有界查询生成共同对手、资金流入流出关联、可疑归集等线索卡，展示相关交易 ID、时间范围、数据缺口和合法替代解释。先不引入新的图数据库。
2. **离线网络实验。** 在合成客户/账户/交易数据上比较“原单客户特征”与“增加网络线索”的调查效果；若有稳定收益，再评估图模型。模型输出仍需转成可验证的线索，不直接形成客户结论。

新增诈骗资金相关剧本时，同时设置合法工资发放、商户结算等对照。对可能的受害者、过渡账户和疑似收益方分别记录不确定性，禁止因为相邻账户被标记就自动认定本客户可疑。

### 7.3 案件边界与容量

多个客户的案件以“关联调查组”链接，各自保留客户权限、预警归属和结论；不要突破现有“同客户归并”限制把多个客户硬塞入单案。

现有 `max-linked-alerts` 是单次执行容量，不是业务发现上限。新增网络线索不应要求绕过容量门禁；可以分组展示、分页、由人选择需要形成正式调查假设的线索。任何压缩摘要都必须保留原事实引用与未纳入说明。

**验收：** 交易不重复计数；不同币种不裸加；同名实体不误合并；路径能够逐笔回看；合成合法对照不被系统强行定性；没有授权时看不到其他案件原始证据。

## 8. B5：报告工作底稿与质量复核

### 8.1 业务目标

当前报送实体主要管理理由、状态和受理编号。新增的工作底稿应帮助复核员回答“谁、何时、通过什么账户/交易、出现什么异常、为什么不能合理解释、已经核实什么、仍未知什么”。报告越长不等于质量越高。

### 8.2 底稿与生成过程

- 结构化内容：客户背景、调查范围/截止时点、时间线、关键交易/关系、异常事实、合理解释及核验、残余疑点、建议处置、事实引用。
- AI 根据冻结事实生成候选段落，段落关联 findingId/evidenceId/transactionId；数额、日期和对象来自结构化事实，不能自由编造。
- 缺失材料显示待补项，禁止用通用措辞填满；法规引用标明原文/摘要/内部政策及版本。
- 用户修改形成新的工作底稿版本；人工确认内容不覆盖原始 AI 输出，保留修改差异。
- 技术故障/模型降级要能展示已有事实并允许人工续办，不能自动套用低风险报告。

### 8.3 质量检查和状态

为底稿设置独立状态：草稿、待质检、退回修改、可用于报送准备。继续复用现有案件和报送状态机，避免新增大量主状态。

检查包括事实可追溯、重要反证已处理、金额/币种/时间一致、结论与逐预警覆盖一致、当前版本有效、未知与事实区分。质量缺陷按严重程度返回具体位置，不只显示一个百分数。

可疑报告正式登记前由具有权限的复核员核对；独立质检记录不得由同一人自我代签。首批仍是演示环境的人工登记受理编号，真实报送接口需另行核实格式、权限、重试/重复提交和回执语义。

**验收：** 注入无依据的人名、金额或理由时被检查发现；一条证据更新不会静默改写已确认底稿；退回补正生成新版本并保留原受理记录；资料不全时不能显示“质检通过”。

## 9. B6：以业务结果衡量改进

### 9.1 先建立基线，再讨论收益

用同一批冻结合成案件比较当前版本与新版本，按客户/关联网络/时间切分训练和测试，避免同一客户或同一资金网络同时出现在两边。初期建议建立 120—200 个带正常对照的合成案例，具体数量是实施建议，不是监管要求或统计充分性的保证。

至少覆盖六类既有剧本、新诈骗资金场景、数据缺失、合理解释、版本冲突、资料变更和报告退回。领域复核无法完成时，结论标记“待领域审核”；不得仅因模型与自身生成标签一致就宣称准确。

| 指标 | 定义/测量方式 | 首批建议目标 |
|---|---|---|
| 调查用时 | 固定案例集下，从打开材料到形成可复核结论的有效操作时间，单独统计等待外部材料时间 | 先测基线；试点中位数降低约 20% 作为待验证目标，不承诺达成 |
| 必要事实可追溯率 | 报告中需证据支持的事实，具有有效引用的比例 | 确定性验收样例 100%；人工抽查真实性另算 |
| 严重无依据结论 | 经独立复核认定的人物/金额/关键事实捏造或越权最终决定 | 固定回归集出现一项即阻断；不推断真实世界零错误 |
| 低风险无效工作量 | 合法对照案件的重复材料要求、无关 EDD 项、错误关联数 | 相对基线下降，且必要控制和高风险召回不退化 |
| 覆核退回率 | 按资料不足、事实错误、推理不充分、格式问题分组 | 分类型监测；减少退回不能以放松质检为代价 |
| 漏判与误判 | 在已独立标注的案例集按场景/客户类型分别统计，报告分母和样本不确定性 | 无明显退化；样本不足时不作显著提升声明 |
| 持续尽调履约 | 任务按期完成率、逾期原因、新事件到任务的延迟、重复任务数 | 确定性重复事件不重复建任务，逾期可追责 |
| UBO 可核验完成度 | 候选有可靠依据并经人工核验的比例、未解决差异及逾期 | 不以候选数量或图节点数量作为完成度 |

### 9.2 标签与反馈

将 AI 建议、分析员判断、复核结果、后续质检和外部事实分别保存。人工排除不能直接成为永远正确的负标签；重新调查或新事实可以形成带原因的新标签版本。报送数量、模型赞同率和案件关闭数量都不宜单独作为绩效目标。

沿用冻结评测机制，新增业务案例集版本、剧本版本、证据版本和政策版本。模型、提示、检索或规则改变后都在同一冻结集上比较；关键退化时恢复上一经过验收的版本。

## 10. 统一的数据和接口演进

以下名称为建议，实施时先核对现有实体，避免重复建设。

| 建议对象 | 核心内容 | 更新和追溯规则 |
|---|---|---|
| `CustomerRiskAssessment` | 客户风险、理由、措施、审核、下次复核 | 追加版本，原案件引用原版本 |
| `CustomerDueDiligenceTask` | 触发事件、任务清单、责任人、期限、结果 | 幂等事件键，状态变更加审计 |
| `EvidenceArtifact` / `EvidenceAssessment` | 来源、内容、定位、核验、适用性 | 原始内容不可变；核验可追加/撤销 |
| `BeneficialOwnershipRelation` / `Verification` / `Discrepancy` | 权益/控制路径、核验、差异 | 来源分层，人工结果绑定关系版本 |
| `RelatedInvestigationGroup` | 跨案件关系与共享范围 | 只链接案件，不改变预警/证据所属客户 |
| `ReportWorkingPaper` / `QualityReview` | 段落事实引用、人工修改、质检 | 保留原稿、修订和质检记录 |
| `BusinessOutcomeLabel` | 来源、质量等级、复核人、变更原因 | 不自动覆盖历史标签，不将未核实标签直接用于训练 |

新增接口沿用角色校验、预期版本、稳定冲突码和 Audit Outbox。把允许操作及阻断理由由后端返回，避免前端复制一整套业务门禁。查询可以展示实时客户情况，案件决定必须绑定明确版本和截止时点。

如 B1/B3 引入新的强制证据或核验条件，应显式增加调查策略/契约版本，对新案件小范围启用；存量 v1 保持既有可编辑和结案规则，需升级的活跃案件走明确迁移流程。不能直接修改共用门禁，令全部历史案件突然无法结案。

## 11. 业务验收场景清单

| 编号 | 操作场景 | 关键通过条件 |
|---|---|---|
| BA-01 | 假设冲突后刷新失败，再打开 | 新依据与目标结论保留，没有误提示或自动提交 |
| BA-02 | V25 存量迁移和两阶段 SQL | 原事实/外键/NULL 正确，全部查询执行成功 |
| BA-03 | 输入不存在或无权限的证据引用 | 不能显示为已核验或供越权读取 |
| BA-04 | 证据撤销/有争议，重新形成判断 | 新决定要求处理该变化，历史档案保留 |
| BA-05 | 法规摘要与原文条款共同检索 | 来源类型和适用版本清晰，不伪造条款定位 |
| BA-06 | 资料/交易记录保存起算与保留标记 | 类别、起算事件、政策和调查保留互不混淆 |
| BA-07 | 相同异常在两个不同背景客户出现 | 结果由客户事实和证据决定，不只由场景代码决定 |
| BA-08 | 已结案客户发生重要变化 | 新任务关联旧背景，旧案快照不变 |

| BA-10 | 低风险简化与不可简化条件 | 减少重复材料，但不能绕过未解释异常和人工最终决定 |
| BA-11 | 多层权益与实际控制候选 | 候选、未知和人工核验状态分开，计算可解释 |
| BA-12 | UBO 多来源不一致 | 有差异记录、补证和理由；不静默覆盖 |
| BA-13 | 核验后控制关系再次变化 | 生成复核任务，原结果保留版本 |
| BA-14 | 同名主体、未知对手和跨币种交易 | 不误合并实体，不将原币金额直接混加 |
| BA-15 | 合成资金网络及合法结算对照 | 线索可逐笔复查，不把关系直接变为犯罪判断 |
| BA-16 | 跨客户关联调查组 | 权限边界生效，不突破同客户归并限制 |
| BA-17 | AI 报告混入无来源关键事实 | 质检指出具体缺陷并阻断使用 |
| BA-18 | 合理解释、反证及未知未处理 | 复核可定位并退回，不被一条支持材料掩盖 |
| BA-19 | 报告质检/登记/退回补正 | 版本、审计、受理信息及人工责任连续 |
| BA-20 | 模型不可用或更换版本 | 保留事实、明确降级、不自动低风险结案；新版本经固定集对照 |

每个场景都提供正常路径、反例和预期数据变化。数据库/队列场景在真实隔离依赖中执行；页面交互在组件和浏览器分别测试；领域质量通过独立复核，不能由代码测试替代。

### 最小演示故事

选择三组可复现合成客户：有经营凭证的季节性交易增长、业务背景不足的异常资金过渡、具有控制关系差异的企业客户。分别演示合理解释、继续调查/可疑处理、UBO 差异核验；再改变一项资料触发持续复核。最后展示同一批案件的原版本/新版本调查用时与质检结果，而不是只播放模型生成文本。

## 13. 风险、依赖与发布治理

- **领域规则未确认：** 新剧本和 UBO 规则先作为待审核策略，未审核不启用强制自动判断。保存政策与条款映射逐项核实。
- **数据质量不足：** 缺 ID/来源/时点时不建设看似精确的资金路径；先展示缺口并补数据契约。
- **新门禁影响存量：** 策略版本与案件绑定，新增强制项分批启用，历史只读记录不被重写。
- **效率优化压低风险识别：** 同时检查合法对照、高风险案例与严重错误，不能以少报/快关案作为唯一成功指标。
- **外部信息或模型依赖：** 超时、数据断供和模型切换均有可见降级；无合法接入条件时仅提供接口设计或合成演示。
- **隐私与调查保密：** 原始证据按业务需要授权，导出记录范围与用途；提供客户材料时不得把内部可疑判断无差别向客户展示。

每批发布前执行迁移和兼容测试，在新案件小范围启用；保留已有快照/模型/法规/策略版本。出现证据错配或越权决定，停止受影响新功能，回到经验证的版本，不删除新增历史事实。

## 14. 最终交付和验收标准

交付业务规则与场景说明、对象/接口定义、实现及迁移、合成数据、角色操作脚本、实际测试/质检报告、版本说明和回退方案。每个包写明已实现、已执行验证及仍未执行的内容。

业务优化有效的判断是：能基于客户背景解释异常，证据和 UBO 结论可核验，变化能触发持续复核，报告可被独立人员复现，合法对照的无效工作量下降，同时关键风险和人工责任边界不退化。模型、图或 Agent 的数量不作为完成标准。
