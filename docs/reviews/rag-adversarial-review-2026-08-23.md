# RAG 企业化改造对抗性审查（2026-08-23）

## 1. 审查结论

本轮已把法规 RAG 从“返回相似文本的搜索功能”推进为具备结构化授权、适用期、证据归属、版本发布、回滚、隔离、审计、评测和拒答能力的证据服务。单元、数据库迁移、真实 PGVector、Redis、权限和 Agent E2E 均有自动化验证。

结论不是“已经达到生产完备”。当前最主要的剩余限制是：评测集只有 18 条且仍待领域专家复核；语料规模只有 22 个片段；本地精排冷缓存 P95 为 671ms；尚未接入真实生产影子流量。因而可以作为有工程深度的校招项目经历，但不能表述为已在银行生产投产或已达到生产准确率。

## 2. 对抗矩阵

| 攻击/故障假设 | 审查结果 | 已采取的防线 |
|---|---|---|
| 最近邻与问题无关，却被模型包装成法规依据 | 通过 | 词法覆盖阈值、证据强度门控、显式 `NO_RELEVANT/INSUFFICIENT`，未知异常不伪装成空证据 |
| 无权限文档占满 Top-K 或越权返回 | 通过 | jurisdiction/accessScopes 存储层下推，服务层精确 scope 二次校验，主题证据冻结 |
| 损坏/旧元数据默认变成公开可信 | 已发现并修复 | 元数据缺失默认 `QUARANTINED/UNTRUSTED_METADATA/INVALID`，不再 fail-open |
| 过期或未来生效法规进入结论 | 通过 | `asOfTime` 与 effectiveFrom/effectiveTo 二次门控 |
| 辖区或 scope 携带通配、注入式语法 | 通过 | RetrievalRequest 白名单格式、数量/长度限制，SQL 全参数化并转义 LIKE |
| 语料包含提示注入、密钥、身份证或异常文件 | 通过 | 入库前扫描，隔离记录独立提交，只保存摘要和原因码 |
| 构建崩溃留下重复候选，挤占 Top-K | 已发现并修复 | 同 indexVersion 重试前清理候选；ACTIVE 指针不提前切换 |
| 多实例构建租约过期后旧实例继续发布 | 通过 | 中央租约、后台心跳、写入与发布前同步确认所有权 |
| 回滚与清理并发，刚激活版本被删除 | 已发现并修复 | 两个状态转换共用 `legal_index_state` 悲观行锁；先提交 `PURGING` 再执行可重试 PG 清理 |
| 缓存跨索引、权限、时间或算法版本污染 | 已发现并修复 | key 包含完整索引身份、权限、法域、日期、embedding/reranker/融合参数、运行时精排状态和 query SHA-256 |
| 精排配置开启但实际从未执行 | 已发现并修复 | 删除 `候选数 <= topK` 的错误短路；增加精排执行单测 |
| 精排运行时状态变化仍写入旧缓存 | 已发现并修复 | 检索前后重算管线身份，状态变化时跳过缓存写入 |
| 模型引用一个证据，却据此执行未被条文支持的动作 | 通过 | evidenceId 归属校验 + `FREEZE_ASSETS/REPORT_TO_AUTHORITY/STOP_FINANCIAL_SERVICE` 直接支持校验 |
| 评测把“能回答”误当作“拒答正确” | 已发现并修复 | 单独输出 noAnswerRefusalRate；召回指标仅以 answerable 案例为分母 |
| 为简历堆砌 GraphRAG/ColBERT 增加不可验证复杂度 | 通过 | ADR 明确暂缓，只有规模、多跳失败占比、独立金标和收益门槛满足后才 PoC |

## 3. 真实验证证据

- 单元测试：最终以 Maven 全量结果为准；真实外部 LLM 用例默认跳过，不混入确定性结果。
- 集成/E2E：覆盖 15 个 Flyway 迁移、Hibernate validate、真实 MySQL/PGVector/Redis、CSRF/RBAC、可靠队列与完整 Agent 工作流。
- RAG DEV v2，18 条：
  - 无精排：Recall@5 93.3%，Top3 93.3%，MRR 81.1%，nDCG@5 84.2%，无答案拒答 100%，P95 135ms；
  - 本地 bge 精排：Recall@5 100%，Top3 100%，MRR 95.6%，nDCG@5 96.7%，无答案拒答 100%，P95 671ms。

这些数字来自本机冷缓存和小语料，标签状态为 `PENDING_DOMAIN_REVIEW`，只用于开发回归与候选比较。

## 4. 未关闭风险与下一道门槛

1. 由 AML/法律专家复核 18 条 DEV 标签，并扩展至少 100 条仓库外冻结 TEST，覆盖法规冲突、修订、跨法域和多跳问题。
2. 在接近生产规模的语料上重测索引大小、Recall、nDCG、无答案、ACL 和 P95；小语料结果不得外推。
3. 本地精排 P95 671ms 虽低于当前 750ms 候选门槛，仍需用 JFR/ONNX profiling 验证微批大小，并在目标硬件复测。
4. 5% 影子 → 5% → 25% → 100% 的策略和回滚手册已定义，但仓库没有真实生产流量路由器；接入部署平台后才能闭环演练。
5. 中文专用 embedding 仅定义了制品身份和迁移协议，尚未通过独立金标比较，因此继续使用实际可验证的 MiniLM/384，不制造“已迁移”结论。
6. 增加 PG/Redis/租约中断、审计库不可用、reranker 熔断的自动化故障注入，而不只依赖单测和运维手册。

## 5. 简历表述边界

可以表述“设计并实现企业级法规 RAG 证据链、索引蓝绿发布/回滚、ACL 与有效期门控、知识投毒隔离及独立评测，并在 18 条 DEV 上将 Recall@5 从 93.3% 提升至 100%”。必须同时标注“合成 DEV、待领域复核”或在面试中主动说明；不得表述为真实银行生产指标。
