## 必须返工的问题

### A1. [P1] 存量覆盖被新门禁阻断，但页面不允许重新确认

位置：`frontend/src/views/CaseDetailView.vue:1037`。

V26 给原有覆盖新增可空 `hypothesis_revision` 且不回填，这是计划明确要求的迁移方式。因此已经 SUSPICIOUS/EXPLAINED 的存量覆盖会保留结论，同时 hypothesisRevision 为 NULL。新门禁正确提示“缺少假设版本绑定，请重新确认”，但页面仍只在 `conclusion === 'PENDING'` 时显示“形成结论”。

已决假设的“修改判断”入口又固定切换到相反状态，不能用于保持原结论、仅重新确认依据。要求用户为了补版本而人为反转调查判断，会破坏业务语义，也可能因缺少反向证据而根本无法操作。

**本轮验证：** 临时 Java 探针调用实际 `InvestigationReadinessEvaluator`，确认 NULL 绑定会阻断最终复核；从当前 Vue SFC 模板提取实际按钮条件并求值，SUSPICIOUS/EXPLAINED + NULL 的按钮结果都为 false，只有 PENDING 为 true。这是服务判断与实际模板条件的验证，不是浏览器端到端测试。

**修正要求：** 可编辑案件上，覆盖为 PENDING、绑定为空、绑定版本过期或关联状态不一致时，都应提供重新确认入口；显示当前假设依据，预填原分析，由用户明确提交当前版本。有效结论无需通过反转假设来补版本。

**回归验收：** 构造 V25 时代的 HOLD 案件，覆盖已经 EXPLAINED 或 SUSPICIOUS；应用 V26 后不修改假设状态，直接在页面重新确认，恢复就绪并完成对应人工处置。

### A2. [P2] 容量错误在进入执行后才抛出，失败案件无法按提示拆分

主要位置：`backend/src/main/java/com/bank/aml/agent/AlertSnapshotAssembler.java:65`。
关联位置：`WorkflowMessageHandler.java:124`、`CaseIntakeService.java:154`。

默认最大关联预警数为 8。建案归并和启动入口没有在案件仍可调整时校验容量，用户可以向 PENDING 案件归并 9 条预警。Worker 抢占后，快照装配抛出 NonRetryableWorkflowException，错误提示要求拆分；消息处理器随即写 FAILED。但是拆分服务只允许 PENDING，页面也不在 FAILED 展示拆分按钮。普通重试会再次入队并再次遇到同样的容量错误。

**本轮验证：** 临时探针向实际 `AlertSnapshotAssembler` 提供 9 条有效 LINKED 预警，得到不可重试容量异常；随后用模拟的 FAILED 案件调用实际 `CaseIntakeService.splitToNewCase`，确认恢复操作被拒绝。Worker 将该异常映射为 FAILED 的代码路径已核对；未在真实 Redis/数据库中执行该完整流程。

**修正要求：** 在归并或启动的短事务中校验容量，超限时保留可调整的 PENDING 状态并提示拆分。还需保证已入队 PENDING 案件不会在等待 Worker 时继续归并至超限；可采用归并边界校验或明确的启动边界机制。Worker 的容量防线继续保留，同时为既有超限失败案件提供受控恢复方案，不能依赖抢在重试消费者前拆分。

**回归验收：** 正常运行 Worker 下，对 8→9 条预警边界测试归并与启动的并发结果；超限请求应在进入不可编辑状态前被拒绝，用户能稳定拆分后继续调查。

### A3. [P2] 存量影响查询引用不存在的列，无法完成升级前排查

位置：`docs/ops/investigation-contract-impact-queries.sql:7`。

首条查询使用 `c.reported_at_alias`，但实际案件表的字段是 `reviewed_at`（V19 迁移新增），源码及迁移中没有定义 reported_at_alias。该查询在真实 MySQL 上会因未知列失败，无法输出“已自动 DONE 但没有最终人工决定”的受影响案件清单。

此外文件顶部说明“V26 迁移前后各执行一次”，但后续多条语句直接查询 V26 才新增的 hypothesis_revision，因此不能把整份脚本原样用于迁移前数据库。

**本轮验证：** 对照查询、实体和迁移定义静态确认；没有对真实数据库执行 SQL。

**修正要求：** 修正列名，将 V26 前可执行的影响查询和 V26 后的版本绑定查询分段或分文件，并标明 schema 前提。

**回归验收：** 在独立数据库分别迁移到 V25、V26，执行各自阶段全部 SELECT；确认无未知列错误，且能命中预设异常案件。
