# AI 小助 V1 分阶段对抗性审查记录

> 日期：2026-08-23  
> 依据：`docs/specs/ai-customer-assistant-v1-spec.md` 与 `docs/plans/ai-customer-assistant-v1-implementation-plan.md`

## 审查规则

每个工作包完成后记录功能验证、主动攻击、发现、修复和剩余风险。测试未执行或依赖环境缺失时必须明确标记，不计为通过。

## WP0：基线、配置与安全开关

- 基线前端单测：通过（4 个文件、13 个测试）。
- 基线前端构建：通过。
- 基线后端测试：首次因沙箱进程未继承用户 `JAVA_HOME` 失败；已定位用户 JDK 为 Corretto 21，改用显式 JDK 与本地 Maven 缓存继续验证，该失败不是项目代码失败。
- 安全默认值：`enabled=false`，生产配置仍需显式开启。
- 配置边界：消息长度、保留期、限流、超时、事件 TTL、租约窗口、历史窗口和工具轮次均有上限。
- 对抗检查：租约 TTL 小于两倍续租周期时校验失败；超大消息上限校验失败。
- 剩余项：功能接口尚未创建，`enabled=false` 的 HTTP 阻断将在 WP6 验证。

## WP1：客户详情上下文

- 新增逻辑删除过滤的 ADMIN 客户详情接口和前端详情路由，证件号只返回掩码。
- 快速切换客户使用请求版本号隔离，旧响应不能覆盖新客户页面。
- 服务测试覆盖启用、停用、已删除与不存在客户；路由角色测试通过。

## WP2：会话、消息、run 与加密持久化

- V16 新增会话、消息、run、快照和工具轨迹五张表，仅新增对象。
- owner 查询、归档/过期状态、`clientMessageId` 幂等和会话悲观锁已实现。
- 独立保留期任务按 100 条批次将到期会话逻辑标记为 EXPIRED，不在请求线程物理删除审计数据。
- 消息与快照使用随机 IV 的 AES-GCM 密文；API 不返回密文或 Entity。
- 对抗结果：其他 owner 统一 404；已归档会话拒绝写入；活动 run 阻止同会话第二次提交。

## WP3：冻结快照与最小权限工具

- 模型视图不含姓名、身份证、数据库主键和交易对手明文；股权主体只保留掩码。
- 七个工具全部只读，四个客户工具参数数量为 0；未知 evidenceId 被拒绝。
- 数据源集合在快照创建后改变不会影响工具结果，快照摘要绑定事实和知识证据。
- 隐私测试扫描 `toString` 和工具返回，未发现完整身份字段。

## WP4：三层 Guard

- 输入层在加载快照前拒绝敏感值/敏感字段索取、写请求、跨客户、注入和非金融问题。
- 流式层保留 64 字符滚动窗口，能够检测被拆分到相邻 chunk 的敏感模式。
- 最终层拒绝未知证据、客户标识、写操作完成声明和确定性事实冲突。
- 70 条合成评测发现“银行概念问题被客户风险词抢占”的优先级缺陷，已增加当前客户显式作用域和概念问句判定；修复后意图分类 70/70，15/15 攻击在模型前阻断。

## WP5：Agent、记忆、租约与恢复

- 每个 run 创建独立 Agent 与快照工具，历史仅从同会话已完成消息重建。
- 独立有界执行器、Redis owner-token 租约、Lua compare-renew/release 和最大工具轮次限制已启用。
- 模型超时、租约丢失、执行器饱和和回调错误均收敛到 FAILED/BLOCKED。
- 对抗审查发现终态可能被迟到回调二次覆盖，已为 run/message 增加单向状态机；启动恢复只终结失联 run，不自动重放模型调用。

## WP6：REST、限流与可重放 SSE

- 接口全部受 ADMIN 角色保护；会话和 run 订阅均再次校验 owner。
- Redis Lua 限流故障时 fail-closed；SSE 使用 run 级 Stream、事件 ID、TTL、重放和终态关闭。
- 前端若错过事件会回查 MySQL 消息事实源。
- 集成安全测试验证：ANALYST 访问助手为 403，ADMIN 可读状态，创建会话缺 CSRF 为 403。

## WP7：前端 AI 抽屉

- 支持会话恢复、流式 delta、终态对账、快捷问题、证据标识和连接状态。
- 关闭抽屉、组件卸载或客户 ID 变化会关闭 EventSource、清空旧消息并废弃旧请求。
- 模型内容只用 Vue 文本插值和 `white-space: pre-wrap`，没有 `v-html`；超长无空格内容可换行。
- 前端测试 15/15、生产构建通过。

## WP8：企业银行知识 RAG

- 两级召回为受控官方公开基线与现有企业法规索引，运行前冻结到快照。
- 公开基线启动时校验 evidenceId、官方 HTTPS 域名、生效日期、类型和长度；动态索引异常降级但不伪装为实时事实。
- 工具只在冻结证据中做局部词法匹配，未知 ACL 不由模型传入。
- 对抗测试覆盖过期知识、部分中文查询、索引版本冻结和快照外证据拒绝。

### 静态与对抗扫描

- `@Tool` 共 7 个，均位于 `CustomerAssistantToolSuite`，未发现写工具；客户工具不接受 customerId。
- 助手日志未记录用户问题、RAG query、消息正文、客户号或密钥。
- 前端助手目录未使用 `v-html`（仅安全注释出现该字符串）。
- 助手模型链未设置 `prompt_cache_retention`。
- 完整身份证只在快照工厂内部用于既有制裁比对，未进入安全视图、工具轨迹、SSE 或模型 Prompt。
- 最终审查发现知识证据白名单原先只识别 `类型:SHA256`，可能漏检伪造的 `KB-*`/`LEGAL-*`；已扩大 evidenceId 语法并新增“伪造拒绝、真实放行”回归测试。

### 未伪造的剩余门禁

- 新增的 70 条助手数据集尚未获授权发送给外部模型，因此本轮未执行“新助手真实 DeepSeek 质量评测”；既有 9 条工单 Agent DEV 授权与结果不冒充新助手结果。
- 当前可以判定代码、确定性安全门禁和基础设施回归通过；生产环境仍保持 `AML_ASSISTANT_ENABLED=false`。
- 在授权合成助手子集并完成真实模型引用有效率、事实一致率和延迟/Token 评测前，不宣称 V1 达到生产发布门禁。
