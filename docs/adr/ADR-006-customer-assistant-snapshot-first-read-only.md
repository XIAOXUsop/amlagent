# ADR-006：当前客户 AI 小助采用 Snapshot First 与无写工具架构

- 状态：Accepted
- 日期：2026-08-23

## 背景

管理员需要在客户详情页询问该客户的交易、股权、制裁、AML 与银行金融问题。系统处理银行客户信息，模型可能遭遇提示词注入、跨客户诱导、流式泄漏、记忆串线和知识过期。

## 决策

1. 会话由后端使用数据库客户主键和管理员用户名绑定，聊天消息不能改变客户。
2. 每个 run 一次性生成脱敏不可变快照；Agent 工具、RAG 和输出校验共享该快照。
3. 客户工具不接受 `customerId`，工具集中不注入业务写服务。
4. 完整消息以 AES-GCM 密文保存在 MySQL，ChatMemory 只由已完成消息重建。
5. 同一会话使用 Redis owner-token 租约串行执行；POST 使用 clientMessageId 幂等。
6. SSE 事件先写 Redis Stream，再向浏览器发送；MySQL 消息是最终对账源。
7. 输入、流式与最终回答分别校验，拒绝写请求、跨客户、敏感数据和伪造证据。
8. AML/银行知识在模型调用前完成检索并冻结，Agent 不能扩大 ACL 或访问实时全局索引。

## 结果

该设计牺牲了任意客户查询和自动操作能力，换取可证明的最小权限、客户隔离、事实一致性和审计复现能力。模型或 Redis 故障时 fail-closed，不回退成无证据的模型常识回答。

## 发布约束

- 生产默认关闭，必须显式开启。
- 新助手的真实模型评测未达到门禁时不得描述为生产可用。
- 未来写操作必须通过独立需求、安全评审和人工确认流程，不能向现有工具集直接加写方法。
