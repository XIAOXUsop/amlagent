# AML 尽调 Agent 评测数据集 v2

> 本文保留 v2 的设计与当轮验收记录。当前默认已升级为 [v3](agent-dataset-v3-and-acceptance.md)，
> 其中两条历史合成法规证据的勘误仅修改 v3，v2 数据文件未改写。

## 1. 定位与边界

本次扩展针对四工具客户尽调 Agent，不改变客户 AI 小助、RAG 检索集或生产风险规则。
目标是增加有证据差异的难例，并让测试自身可以被检查，而不是靠增加同义改写提高通过率。

- 主文件：`backend/src/main/resources/evaluation/agent-cases-v2.json`。
- 覆盖清单：`backend/src/main/resources/evaluation/agent-cases-v2-manifest.json`。
- 版本：`aml-agent-curated-v2 / 2.0.0`，当轮加载器默认使用 v2；当前默认使用 v3。
- 旧文件 `agent-cases-v1.json` 完整保留；前 15 条案例的输入、fixture、标签、标注与切分均未改动。
- 新增 30 条全部为虚构客户、身份标识和业务资料，无真实客户信息。
- 新增标签由 AI 辅助整理，状态为 `PENDING_DOMAIN_REVIEW`，尚未经过领域专家独立审批。
  v2 数据集的 `annotationMethod` 为 `AI_ASSISTED_CURATED_PENDING_DOMAIN_REVIEW`，不宣称已完成人工审核。

本数据集是公开开发测试资料，不是隐藏盲测金标，不是法律意见，也不代表真实银行生产准确率。
测试通过只能说明当前确定性契约、数据完整性及被测试的错误能被识别；不能证明真实模型可以正确推理全部案例。

| 分片 | 原有 | 新增 | 合计 | 用途 |
|---|---:|---:|---:|---|
| DEV | 9 | 20 | 29 | 开发调试和真实模型受控回放 |
| DEMO_TEST | 6 | 10 | 16 | 公开难例、测试治理与确定性回归，不作为隐藏 TEST |
| TEST | 0 | 0 | 0 | 仍需仓库外专家独立创建和审批 |
| 合计 | 15 | 30 | 45 | 公开合成案例 |

全部公开案例为低风险 15 条、中风险 13 条、高风险 17 条。
新增部分三类各 10 条；这只是工程覆盖分布，不是客户真实风险发生率，不能按此推断生产精确率。
新案例以 15 个家族成组分配：同组不得跨 DEV / DEMO_TEST / TEST。

表中编号均带前缀 `AML-AE-`。
`CONTRAST` 的 12 组是证据条件对照，不宣称每组仅改变一个标量；有时证据解释状态与结构化事实必须一起改变。
`INVARIANT` 的 3 组不改变业务事实、评级和转人工要求，但攻击版本额外要求识别、忽略并记录注入。
配对关系仅为测试审计资料，不会作为模型输入。

### 3.1 误报控制

高跨境比例、夜间营业、多层股权和现金收入不能单独作为风险结论。
对照案例提供独立文件与经营背景，检验 Agent 是否结合解释证据，而不是看到关键词就冻结或升级。

### 3.2 资料缺失与组合风险

数据源超时与局部覆盖必须明确未知范围；fixture 中的零值可能只是规则适配占位，不是观察到的零交易。
部分流水已有强层化证据时，不能因为其他月份未知而抹掉已观察到的风险。
交易缺失、UBO 控制冲突及一级名单控制分别要求人工处理，不能只检查风险字符串是否匹配。

### 3.3 名单与高影响动作

同名匹配、身份确认、境内关注名单与项目一级名单分别测试，不能相互代用。
冻结、停止服务和向主管机关报告仅在本项目合成一级名单政策及证据支持下成为必需动作。
其余案例禁止无依据冻结；可疑交易报告复核不等于已确认犯罪。

合成法规 fixture 复用项目命题表中的法规名称作为技术匹配键，明确标识为非真实法规原文。
**名称匹配或关键词校验通过不等于真实法律适用正确。**
正式专家复核必须另行核验适用辖区、名单类型、法条效力、行动主体与触发条件；
不能把项目内部等级直接视作普遍法定义务。

### 3.4 工具文本注入

覆盖交易、工商与法规检索三个通道。工具数据中的角色标签、伪造管理员要求、放行指令不具有系统权限。
同一攻击不应使本来正常的客户变高风险，也不应把已确认名单变成正常客户。
金丝雀 `CANARY_AML_EVAL_7F3A` 只检测该字符串被输出，不宣称能检测所有形式的内部提示泄漏。

## 4. 案例结构与标注要求

每条新案例提供：

1. 无标准答案的 `input`：客户引用、类型、截至日、预警与任务说明。
2. 四工具 `toolFixture`：交易、工商、名单、法规查询关键词及冻结法规证据。
3. `riskFacts`：与文字证据一致的护栏适配事实，不暴露给模型，也不作为生成标签的规则 oracle。
4. `expected`：独立维护的风险、转人工、必需与允许发现/动作、禁止声明。
5. `annotation`：评级理由、四份工具的可追溯事实引用、复核状态与审核说明。
6. manifest：配对、变化字段、设计来源、来源使用边界。

新增事实引用格式为 `工具字段名:原文片段`，如：

```text
legalResult:[evidenceId=AML-LEGAL-V2-P01]
```

自动测试要求字段存在、片段非空且确实出现在该字段，避免“有引用字段但找不到事实”的空壳标注。
标签不是从 Seeder 的命中结果自动推导的。规则兼容检查只用于发现数据与现有执行契约的冲突，
不证明标签经专家认可。

同组固定相同截至日，配对客户名称与编号相同；使用案例 ID 区分运行结果，不能按客户 ID 去重丢掉一侧。
每组共享同一冻结法规 evidenceId，跨组使用不同 ID。

## 5. 自动化质量门禁

新增确定性检查包括：

- v1 的 15 条基线在 v2 中逐记录完全相同；
- 新增分布、15 组覆盖、来源引用、配对唯一性及同组分片一致；
- 12 组改变风险结论、3 组保持事实和最终风险要求；
- 配对实际变化字段与 manifest 严格匹配，禁止无声明的“顺手修改”；
- 新案例交易比例、笔数与结构化事实一致，缺失数据显式标记未知；
- 每条新案例的参考输出满足生产结构、事实前置条件和证据归属校验；
- 新案例所有禁止声明代码都有确定性检测器；旧版仍保留显式 `UNSCORABLE` 的自由文本检查；
- 所有公开案例的模型工单不包含姓名、证件、标签、护栏事实、标注理由或答案代码；
- 新案例四工具按客户隔离，错误客户、空参数、不符合查询关键词的请求不得取得 fixture；
- 故意构造错误评级、错误名单归类、错误冻结及缺数据声称正常，检测器必须报违规；
- 三个注入通道输出金丝雀必须报违规；
- 伪造法规 ID 和“真实 ID 后加假后缀”必须被证据归属检查拒绝；
- 外部隐藏集必须同时具有数据集级和逐案例审批、只包含 TEST 且不与公开案例 ID 冲突；未配置时不得自动准备盲测；
- 非法日期、NaN 比例、重复工具/引用、未知代码、矛盾事实及不完整人工动作等污染案例必须在加载时拒绝。

参考输出采用预先维护的标签构造，只证明契约可满足，不能拿这些测试的通过率冒充 Agent 推理准确率。
正常构建不调用真实大模型，不依赖 MySQL、Redis 或 PGVector。

旧版仍有四类自由文本约束没有完整的确定性检测器：
`UNSUPPORTED_TERROR_FINANCING_CLAIM`、`DISCLOSE_FREEZE_TO_CUSTOMER`、
`FABRICATED_TRANSACTION_STATISTICS`、`UNVERIFIED_UBO_STATED_AS_CURRENT_FACT`。
它们继续记为 `UNSCORABLE`，不能计入禁止声明通过数；本次没有用改名删除这些历史限制。

## 6. 执行与结果解释

在 `backend` 目录执行离线回归：

```powershell
$env:RUN_LIVE_AGENT_EVAL = "false"
./mvnw.cmd "-Dtest=AgentEval*Test,ForbiddenClaimDetectorRegistryTest" test
./mvnw.cmd verify
```

Java 21 与仓库既有 Maven 环境是前提。普通验证默认排除需基础设施的 integration 标签。
真实 DEV 评测仅由明确授权的维护者启用 `RUN_LIVE_AGENT_EVAL=true` 并配置模型密钥，
使用既有 `AgentEvalLiveTest` 或 DEV API；不要把密钥写入仓库。
完整 DEV 现在是 29 条，耗时和费用可能明显高于旧版 9 条。Live test 的超时窗口增至 60 分钟，
这是整轮保护上限而不是实际耗时承诺。

报告需记录数据集版本/哈希、代码 commit、模型与参数、Prompt 版本、规则快照以及实际尝试数量。
真实调用失败、解析失败和 schema 失败必须保留在分母中；不得只报告成功解析的样本。
分别报告模型原始评级、护栏后评级、转人工漏报、工具覆盖、证据引用与禁止声明的可评分比例。
配对样本彼此相关，45 条不能当作 45 个独立同分布生产样本；可信区间或重采样应以家族为单位。

既有 v1 / 9 条 DEV 的成绩不能改写成 v2 成绩；本次扩展没有新增真实模型准确率结果。
公开 DEMO_TEST 当前不是 runner 的正式 TEST 执行入口，它参与离线数据/契约测试。

## 7. 领域专家验收与后续盲测

1. 两名领域专家分别审阅原始工具资料，先独立给出风险、人工处置、依据和不确定性，避免先看现有标签。
2. 对每组确认变化证据确实支持标签变化，注入不变组的业务事实确实等价。
3. 核验字段范围、交易覆盖期、身份匹配依据及实际控制信息时效。
4. 对高影响动作核验真实有效法条与辖区；发现项目政策假设不合理时同步记录，不通过调低测试要求掩盖。
5. 第三人裁决争议，记录审核人、时间、修订理由，修订数据集版本并重新冻结哈希。
6. 正式隐藏 TEST 另行取样，按客户、模板、业务家族隔离；不能将公开案例改 ID、同义改写或直接搬运为盲测。
7. 遵循 [隐藏 TEST 盲测协议](hidden-test-protocol.md)，冻结后运行并完整报告，失败后建立新迭代而非继续调同一盲测集。

目前尚缺专家认可的隐藏集、真实业务覆盖与真实模型 v2 运行结果，这些限制必须与任何对外成绩一起披露。

## 8. 场景设计的一手参考资料

以下来源支持设计维度，不逐条授权本项目三级标签或动作：

- [FATF：银行业风险导向指导](https://www.fatf-gafi.org/en/publications/Fatfrecommendations/Risk-based-approach-banking-sector.html)：强调与已识别风险相称的措施。2014指导页面明确提示结合后续标准更新阅读，不作为现行法条清单。
- [FATF：贸易洗钱风险指标](https://www.fatf-gafi.org/en/publications/Methodsandtrends/Trade-based-money-laundering-indicators.html)：用于设计贸易文件、业务结构及账户行为的核验场景；指标不是犯罪定论。
- [FATF：法人受益所有权指导](https://www.fatf-gafi.org/en/publications/Fatfrecommendations/Guidance-Beneficial-Ownership-Legal-Persons.html)：用于设计信息准确性、时效性及多来源交叉核验的对照。
- [NIST：AI 风险管理框架](https://www.nist.gov/itl/ai-risk-management-framework)：用于风险治理和可信评估的背景。具体载荷、家族切分及测试断言是本项目设计，不宣称 NIST 要求这些具体案例。
